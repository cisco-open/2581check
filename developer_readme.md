# Developer README - 2581check IPC-2581 XML Validator

## 1) Purpose and Scope

This document explains the full application from a developer and code-review perspective, including:

- Python runtime architecture
- Cython conversion and compilation workflow
- Build and packaging workflow
- Utility scripts (versioning and maintenance)
- Data and configuration files

The project is a desktop XML/XSD validation tool focused on large IPC-2581 files, built with PyQt5 and lxml.

Primary application and scripts:

## 3) Runtime Architecture (Python Part)

Main executable module:

- 2581check.py

Main runtime components:

1. ValidationWorker (QThread)
2. XMLLoader (QThread)
3. XMLValidatorGUI (QMainWindow)
4. main() startup function

### 3.1 ValidationWorker

Role:

- Runs XML validation off the UI thread.
- Reports progress, errors, and completion through Qt signals.

Key responsibilities:

- Supports local XSD file or XSD URL.
- Downloads remote schema into a temporary file when needed.
- Preloads XML lines for error line correction.
- Validates XML via lxml.etree.XMLSchema.
- Processes schema errors and attempts to correct truncated line 65535 issues.
- Writes a debug report beside the XML file as {xml_name}_DEBUG.txt.

Core signals:

- progress_updated(int, str)
- validation_completed(bool, list)
- error_occurred(str)
- debug_message(str)

Notable behavior:

- If lxml reports line 65535 repeatedly for very large XML, the worker uses message parsing plus element-based searching to estimate real line numbers.
- Tracks per-element search positions to reduce repeated false matches.

### 3.2 XMLLoader

Role:

- Loads large XML files asynchronously for display.

Key behavior:

- Reads full file content.
- Splits into lines.
- Reports loading and rendering progress.
- Returns both raw content and line list to GUI thread.

### 3.3 XMLValidatorGUI

Role:

- Full user interface, configuration persistence, and user actions.

Major feature groups:

- File selection:
  - Local XSD selection
  - XSD URL entry, browser launch, direct URL download to file
  - XML data file selection
- Validation:
  - Launch/cancel validation worker
  - Display categorized errors/warnings
- Analysis checks:
  - Check for type="OTHER" comment="..."
  - Check for NonstandardAttribute usage
- Error handling UI:
  - Dynamic filter checkboxes by category
  - Grouped error rendering
  - Configurable per-type display limits (session-only)
  - Clickable line links in error output
- XML viewer:
  - Full-text display with line number pane
  - Go-to-line navigation
  - Scroll synchronization
  - Copy selected or full XML text
- Search:
  - Find/next/previous within error panel
- Appearance and persistence:
  - Configurable font sizes
  - Saved window geometry and splitter sizes
  - Saved recent XSD/XML selections

### 3.4 Startup and Lifecycle

Startup flow:

1. QApplication created.
2. XMLValidatorGUI instantiated.
3. Config loaded from 2581check_config.json.
4. UI built and signal connections registered.
5. Window/splitter layout restored.

Shutdown flow:

- closeEvent persists current configuration to json.


## 4) Data Flow During Validation

1. User selects XSD (file or URL) and XML file.
2. GUI starts ValidationWorker thread.
3. Worker optionally downloads XSD from URL.
4. Worker preloads XML lines for large-file line correction.
5. Worker parses XSD and XML with lxml.etree.
6. Worker validates XML against schema.
7. Worker transforms and emits processed error objects.
8. GUI updates filter panel and rich error display.
9. Optional: user loads XML viewer and navigates by line links.
10. Optional: user saves full error log as .log beside XML file.


## 5) Cython Part

Important: the Cython artifacts are not currently committed in the working root. They are generated by script.

Generation script:

- convert_to_cython.py

What it does:

1. Creates a project subdirectory under the repo root:
  - ./2581check_Distribution
2. Creates distribution subfolders:
   - src
   - build
   - dist
3. Copies 2581check.py into distribution src.
4. Extracts and writes Cython module:
   - src/validation_core.pyx
5. Creates hybrid GUI script using Python fallback:
   - src/2581check_pyqt5_hybrid.py
6. Creates setup.py for Cython extension build.
7. Creates build scripts:
   - build_distribution.ps1
   - build_distribution.bat

### 5.1 validation_core.pyx design intent

The generated Cython class ValidationCore focuses on performance-critical routines:

- XML line preload
- Element index construction
- Error message cleanup
- Fast line-number lookup for truncated 65535 errors
- Error categorization

Optimization settings include bounds-check disabling and wraparound disabling for speed.

### 5.2 Hybrid runtime behavior

Generated hybrid app attempts to import validation_core.

- If import succeeds: worker paths use Cython methods.
- If import fails: worker falls back to pure Python behavior.

This supports running the same app with or without compiled extension.


## 6) Build and Packaging Part

There are two build tracks:

### 6.1 Direct Python run (current root)

- setup.bat installs runtime dependencies.
- run.bat launches python 2581check.py.

### 6.2 Generated distribution build (from convert_to_cython.py)

Build script location:

- ./2581check_Distribution/build_distribution.ps1

Script stages:

1. Verify Cython, PyQt5, lxml imports.
2. Clean previous build artifacts.
3. Run: python setup.py build_ext --inplace
4. Copy resulting validation_core*.pyd into src.
5. Smoke-test module import.
6. Use PyInstaller to create one-file windowed executable:
   - Name target: 2581check.exe
7. Move executable into distribution dist folder.

Batch launcher:

- build_distribution.bat invokes the PowerShell script with execution policy bypass.

## 8) Configuration and State

Configuration file:

- 2581check_config.json

Persisted values:

- xsd_file (path or URL)
- xml_file
- text_pane_font_size
- button_font_size
- line_numbers_font_size
- header_font_size
- window_geometry

  - Value is intentionally not loaded from or saved to 2581check_config.json.

Runtime usage:

- Loaded on startup.
- Saved on key changes and on close.

## 11) Suggested Developer Workflows

### 11.1 Run app locally

1. Install dependencies from requirements.txt.
2. Run python 2581check.py (or run.bat).

### 11.2 Validate a target file

1. Select XSD file or enter URL.
2. Select XML file.
3. Click Validate XML.
4. Optionally load XML viewer and click line links.
5. Save .log if needed.

### 11.3 Prepare Cython distribution project

1. Run python convert_to_cython.py.
2. Move to generated ./2581check_Distribution folder.
3. Run build_distribution.bat.
4. Verify output executable and module loading.

## 12) Known Design Tradeoffs

- Large XML files are fully read into memory for both validation and viewer features.
- Error-line correction logic uses heuristic matching for some schema message forms.
- UI does substantial formatting and grouping in the main thread after worker completion.
- Utility scripts are practical but somewhat overlapping.
